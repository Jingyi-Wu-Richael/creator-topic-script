# AI选题发现的默认信息源

仅在用户需要广泛发现AI选题时读取。用户指定行业、语言或来源集合优先；研究一个已知主题时直达相关原文，不必巡查全部来源。

| 来源 | 入口 | 主要作用 | 使用时注意 |
|---|---|---|---|
| OpenAI News | https://openai.com/news/ | 模型、产品、API及研究发布 | 分清产品公告、研究成果、访问限制 |
| Anthropic News | https://www.anthropic.com/news | Claude、Agent、研究和产品更新 | 功能与实验结果分别查原文 |
| Google DeepMind | https://deepmind.google/blog/ | Gemini、生成媒体、科学与机器人研究 | 研究展示不代表产品已开放 |
| Meta AI | https://ai.meta.com/blog/ | 开放模型、视觉、基础设施 | 权重开放不等于任意商业使用，查看具体许可 |
| Microsoft Research | https://www.microsoft.com/en-us/research/blog/ | 系统、Agent、生产力研究 | 原型不等于Office或Azure已上线功能 |
| arXiv | https://arxiv.org/list/cs.AI/recent ， https://arxiv.org/list/cs.LG/recent ， https://arxiv.org/list/cs.CL/recent | 研究原文、方法与实验条件 | 预印本及具体版本；不是同行评审保证 |
| Hugging Face Papers | https://huggingface.co/papers | 论文发现、演示与社区线索 | 回到论文/模型卡核实结论 |
| GitHub Trending | https://github.com/trending | 开源项目发现 | 读README、release、license；星数不证明质量或增长 |

| The Batch | https://www.deeplearning.ai/the-batch/ | 行业背景与综合线索 | 二手归纳回溯原文；周刊不冒充当日消息 |

入口为起点，不保证永久有效。发生跳转或失效时，从官方页面导航或一次针对性检索寻找当前入口，记录实际访问页面，避免反复猜URL。

## 扫描范围

“今天”按用户时区的当日截至当前时刻；“过去24小时”按滚动窗口；“本周”按当周截至当前时刻。先写清查询日期范围，日期由运行环境获取，不硬编码年份。资料稀少时可以扩展窗口，但必须明示，不能悄悄把7天内容归入今天。

默认广泛日报：优先覆盖上述10个来源中的至少6个，并横跨官方公告、研究/开源、评测或行业背景。这个覆盖目标服务于发现多样性；访问受限时报告实际已读数、无更新数和失败项，不声称完成全量扫描，不无限重试。用户指定更窄范围时按窄范围执行。

“完成读取但没有新信息”与“无法访问”分别记录。覆盖数量以实际读取为准，搜索结果里出现该网站不算已读。

核心主题之外留出一两个相邻方向作为探索候选，例如AI工具调研里补充真实使用问题。避免机械分配20%查询；同一公司多个产品只有存在不同观众问题时才分开推荐。

X、Reddit、Newsletter与用户推荐账号用于发现问题、案例和争议。用户未要求读取其私人关注列表、收藏或互动记录时不自动读取。社交平台仅一次截面的互动数字不能推出“持续上升”。

## 搜索与停止

围绕“具体主体＋事件/功能＋时间范围”做针对性查询，先查看最相关的原始来源。找到足够证据后停止同义词搜索。日常发现默认先形成5至8个有来源的候选事件，再深查最适合的3至5个；不足时如实少交。

相同报道转载多次只算同一证据链。保留发布日期、事件发生日期、访问日期三者区别。没有历史快照或可比时间序列时，不写“排名暴涨”“热度上升”或“越来越多人用”。
